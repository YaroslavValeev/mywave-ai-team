# Expert profile model (Phase 9.9)

Формализация экспертного профиля по домену. Baseline: один профиль на домен.

---

## Поля экспертного профиля

| Поле | Описание |
|------|----------|
| **expert_profile_key** | Идентификатор профиля (может совпадать с domain_key при одном профиле на домен). |
| **domain_key** | Ссылка на домен в registry. |
| **profile_name** | Человекочитаемое название профиля. |
| **scope** | Краткое описание области применения экспертизы. |
| **strengths** | Сильные стороны (список). |
| **methods** | Типовые методы и практики. |
| **typical_outputs** | Что обычно выдаёт этот профиль (документы, рекомендации, отчёты). |
| **good_for** | Для каких запросов/задач подходит. |
| **not_for** | Для чего не подходит (ограничения). |
| **context_pack_sections** | Какие разделы включать в context pack (summary, strengths, tools, methods, …). |

---

## Связь с domain registry

Профиль строится на основе записи домена в registry; при необходимости дополняется полями из source_file или из отдельной конфигурации. На этапе 9.9 допустимо формировать профиль целиком из registry (summary, routing_keywords, typical_requests → strengths, good_for).

---

## Использование

- **Routing:** по task_text выбирается домен(ы); для каждого домена подставляется expert profile для объяснения «почему этот эксперт».
- **Context pack:** секции профиля (scope, strengths, methods, good_for, not_for) входят в пакет контекста для промптов и рекомендаций.
