# Expert routing heuristics (Phase 9.9)

Правила определения primary/secondary domain и формирование объяснений (explainability).

---

## Как определяется primary domain

1. **Keyword matching:** Текст задачи нормализуется (нижний регистр, разбиение на слова). Для каждого домена считаются совпадения с `routing_keywords` и `routing_signals`. Домен с максимальным числом совпадений при положительном счёте — кандидат в primary.
2. **Typical requests:** Если в тексте задачи есть явное совпадение с фразой из `typical_requests` домена (подстрока или нормализованное вхождение), этому домену добавляется вес.
3. **Tie-break:** При равенстве счётов используется `fallback_priority` (меньше — выше приоритет).
4. **Порог:** Если лучший счёт ниже минимального порога (например 1), primary может быть не назначен; тогда возвращается fallback или «general».

---

## Как определяется secondary domain

- Домены с положительным счётом, но меньшим, чем у primary, упорядочиваются по убыванию счёта. Берутся следующие до limit (например 2–3).
- Secondary не дублирует primary.

---

## Как срабатывает fallback

- Если ни один домен не набрал порог, возвращается домен с наименьшим `fallback_priority` (например development или analytics как универсальные) либо явный «general» с объяснением «no strong match».
- Fallback помечается в результате как `is_fallback: true`.

---

## Explainability

Для каждого подобранного домена в ответ добавляется:
- **matched_keywords** — список ключевых слов из текста задачи, совпавших с routing_keywords/typical_requests домена.
- **reason** — краткая текстовая причина, например: «Совпадения: договор, юрист, согласование» для legal.
- **score** — полученный счёт (если реализация его считает).
- **is_primary** / **is_secondary** / **is_fallback** — тип назначения.

Пользователь (owner/GM) должен видеть, почему задаче предложен именно этот домен, без opaque scoring.
