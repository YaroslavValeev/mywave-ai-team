# Реестр поставки проектов

Этот формат отделяет состояние исходников, CI, runtime и приёмку результата.
Файл delivery-registry.example.json содержит вымышленные данные. Рабочий реестр
с private-репозиториями, локальными путями и эксплуатационными сведениями хранится
в приватном рабочем пространстве владельца, а не в публичном репозитории.

## Поля

- schema_version и as_of — версия формата и дата снимка.
- id, kind, repository, main_sha — проект, классификация и полная версия исходников.
- ci — результат проверки конкретного SHA и ссылка на доказательство.
- deployment — отдельная среда и состояние unknown / historical / observed.
  Неизвестный runtime имеет sha=null. Старое наблюдение помечается historical.
- acceptance — not_verified / blocked / accepted; принятие требует отдельного
  принимающего, даты и пройденных ворот со ссылками на доказательства.
- owns_domains — единственный канонический владелец каждого домена данных.
  Например, коммерческая бронь и операции смены — разные домены.

Успешный CI не устанавливает deployed SHA и не означает бизнес-приёмку.
Присутствие ссылки и имени принимающего не доказывает их содержание независимо:
это структурный валидатор, а не автоматический reviewer. Авторитетные значения
должны поступать из исходной системы и отдельного процесса приёмки.

## Проверка

Из корня checkout, локальный PowerShell:

    python scripts/validate_delivery_registry.py docs/portfolio/delivery-registry.example.json
    python -m unittest discover -s tests -p test_delivery_registry.py -v

Для рабочего снимка передайте путь к приватному JSON первым аргументом.
Валидатор не выполняет сеть, не изменяет файл и не печатает отвергнутые значения.
Он проверяет также секреты в ключах JSON и credential-bearing URL.

В Docker, с уже подготовленным Python QA image и read-only mount checkout,
выполните те же команды. Не используйте production secrets, сеть или тома БД.
Проверка Docker в сопроводительном отчёте относится только к этому валидатору,
а не ко всему AI-Team или production runtime.

## Обновление и откат

Получить свежие GitHub refs/checks, локальный статус и отдельное runtime evidence;
обновить as_of; устаревшие runtime наблюдения перевести в historical; выполнить
валидатор; передать приёмку ответственному. Не переносить main_sha в deployment
по предположению. Не объявлять планы, smoke-данные и feedback завершённым бизнесом.

Откат — revert этого пакета документации и валидатора; миграций и runtime
изменений нет. В CI Python 3.11 новые unittest-тесты также обнаруживаются pytest.
