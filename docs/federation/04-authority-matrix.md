# Матрица полномочий и подтверждений

Уровни из письма не являются линейным переключателем «больше автономности».
У действия могут одновременно требоваться официальный мандат, approval и
человеческое выполнение. Policy вычисляет совокупность требований.

| Действие | Уровень | Что разрешено | Что блокирует выполнение |
|---|---|---|---|
| Прочитать, сравнить, подготовить внутренний обзор | 0 | в разрешённом workspace | нет membership/source rights |
| Создать внутреннюю задачу/напомнить/обновить derived статус | 0 | с источником, audit и idempotency | неизвестный workspace или попытка подтвердить официальный факт |
| Письмо, сообщение, публикация, предложение, изменение KPI | 1 | подготовить draft; применить только согласованный payload | нет owner approval, payload/адресат/версия изменились |
| Подписать, заплатить, подать официально, позвонить, поехать | 2 | карточка и материалы; owner выполняет физически | агенту исполнение запрещено даже при approval |
| Договор/финансы/кадры/официальная позиция Федерации | 3 + 1/2 | подготовить; дальнейшее действие согласно проверенному мандату | нет официального источника, срок истёк или scope не подходит |
| Чтение чувствительных данных | 3 + data policy | только минимум для явно разрешённой цели | нет отдельного подтверждённого основания и доступа |
| Медицинское, судейское, тренерское решение вне компетенции | 3 + профильный человек | подготовить вопрос/контекст компетентному специалисту | owner approval не заменяет компетенцию |
| F→J/M передача или общее коммерческое предложение | 1 + grant/мандат при необходимости | точная согласованная проекция | членство в обоих контурах само по себе недостаточно |
| Merge/deploy, смена booking writer | существующий execution Owner Gate | по отдельной заданной политике | эта модель не расширяет прежние разрешения |

Approval связывает actor, workspace/project, action_kind, адресата, payload hash,
record version, срок и policy/mandate version. Отзыв/смена условий аннулируют
ожидающее действие. Проверка проводится при подготовке и непосредственно перед
исполнением; replay запрещён idempotency key и execution ledger.
Подтверждение документа не означает согласия на отправку любому адресату.

## Физическое действие

Предлагаемый lifecycle: DRAFT → READY → WAIT_HUMAN → REPORTED → VERIFIED/CLOSED;
возможны NEED_INFO/CANCELLED. READY означает готовность материалов, не результата.
REPORTED фиксирует слова человека; VERIFIED требует предусмотренного evidence.
Ожидание письма до 18:00 создаёт контроль, не фиктивное подтверждение письма.

Обязательная карточка: цель, ответственный, контакт, основание, deadline/timezone,
ожидаемый результат, сценарий, ссылки на материалы, запреты/границы, next_step.
Ответ «созвонился» привязывается к конкретному action_id; при неоднозначности
нужен выбор, нельзя закрыть все похожие карточки. Повтор голосового события не
повторяет задачи или сообщения. Расшифровка/выделенные факты показываются для
исправления; автоматический follow-up остаётся draft до отдельного approval.

## Каноническое решение

Новая подтверждённая revision явно ссылается на заменённую; сохраняются дата,
подтвердивший и причина. Неоднозначное противоречие создаёт review, а не молча
переписывает текущий контекст. Заявленные должности и бюджетные полномочия из
письма остаются hypothesis до проверки официального источника.
